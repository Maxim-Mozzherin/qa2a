# iiko Parser & Accounting Microservice (Bugh-Team)

Высокопроизводительный серверный микросервис на языке **Go (Golang)** для автоматизированного распознавания товарных накладных (УПД, ТОРГ-12, кассовых чеков) с помощью мультимодальных нейросетей, проведения сверки взаиморасчетов, интеграции с **iiko RMS** и построения сквозной рыночной аналитики закупок.

---

## 🚀 Ключевые возможности

### 1. Мультимодальный AI-парсер накладных
* **Поддержка форматов**: Многостраничные документы PDF, сканы и фотографии (JPEG, PNG, WebP), текстовые файлы и выгрузки.
* **Отказоустойчивый LLM-шлюз**: Поддержка каскада моделей (по умолчанию `gemini/gemini-3.5-flash,gemini/gemini-3.0-flash`) с автоматическими повторными попытками и переключением на резервные модели при сетевых сбоях или исчерпании квот.
* **Защита от галлюцинаций**:
  * Использование микро-якорей внимания (`original_prefix`), принуждающих модель фиксировать точные первые слова с оригинала.
  * Игнорирование рукописных пометок, галочек и визуального шума.
  * Фильтрация кодов единиц измерения по классификатору ОКЕИ (796 — шт, 778 — упак, 166 — кг) для исключения подмены количества товара кодом единицы измерения.
* **Интеллектуальный расчет коэффициента фасовки (`ai_multiplier`)**:
  * Автоматический пересчет коробок, упаковок, фасовок в базовые складские единицы iiko (кг, л, шт).
  * Выделение сухого веса консервированной продукции (кукуруза, ананасы, горошек).
  * Распознавание фасовки листовых товаров (нори), упаковок чая, грибов и др.

### 2. Прямая интеграция с iiko RMS
* **Синхронизация номенклатуры**: Автоматическое сопоставление товаров поставщика с базой номенклатуры ресторана в iiko RMS по наименованию и истории сопоставлений (`product_mappings`).
* **Бесшовное проведение накладных**: Формирование валидного XML-документа `incomingInvoice` и отправка в REST API iiko RMS (`/resto/api/documents/import/incomingInvoice`).
* **Автоматическое обучение маппингов**: Запоминание сопоставлений номенклатуры, складов (`store_mappings`) и поставщиков (`supplier_mappings`) по ИНН и UUID.

### 3. Сверка взаиморасчетов (Акты сверки)
* **Нейросетевое извлечение операций**: Парсинг отгрузок (дебет/продажа) из актов сверки поставщиков с исключением платежей.
* **Автоматическое сопоставление**: Интеллектуальный матчинг с записями в базе данных с допустимым порогом расхождений (дельта до 2.00 ₽ для компенсации округлений).
* **Классификация статусов**:
  * `matched` — документ сошелся по сумме и номеру.
  * `mismatched` — расхождение в сумме накладной.
  * `missing_in_db` — операция есть в акте сверки, но отсутствует в учетной базе.
  * `phantom_in_db` — накладная числится в базе, но не заявлена поставщиком в акте.

### 4. Рыночная аналитика и мониторинг цен (Market Intelligence)
* **Sentinel скачков цен**: Автоматическое выявление удорожания товара более чем на 15% относительно 30-дневной медианы с мгновенной отправкой алерта руководству в Telegram.
* **Радар арбитража**: Сравнение закупочных цен разных ресторанов сети на идентичные товары от одних поставщиков.
* **Детектор ползучей инфляции**: Анализ трендов роста стоимости сырья за 30, 60 и 90 дней.
* **Индекс зависимости**: Оценка критической зависимости заведения от монопольных поставщиков (доля > 60% оборота).
* **Анализ токсичных списаний**: Расчет прямых финансовых потерь заведения от порчи и списаний продуктов на основе реальных закупочных цен.

### 5. Безопасность корпоративного уровня
* **Защита от SSRF и DNS-Rebinding**: Собственный сетевой транспорт `netutil.NewSafeHTTPTransport` блокирует обращения к приватным сетям (RFC 1918), loopback, link-local и облачным метаданным (169.254.169.254).
* **Стойкая криптография**: Шифрование паролей iiko RMS алгоритмом **AES-256-GCM** с деривацией ключа через **PBKDF2** (100 000 итераций SHA-256) и поддержкой плавной миграции со старых ключей.
* **Многоуровневый RBAC**: Разделение прав доступа между ролями `superadmin`, `global_accountant`, `admin` и `accountant` с изоляцией по фирмам (`accounting_firm_id`).
* **Защита от брутфорса**: Скользящие лимитеры частоты запросов (`pkg/ratelimit`) на авторизацию и регистрацию с защитой от спуфинга IP-адресов.
* **Безопасная отдача статики**: Запрет листинга директорий через `neuteredFileSystem`.

## ⚙️ Переменные окружения (.env)

| Переменная | Обязательна | Описание | Пример |
|---|:---:|---|---|
| `PORT` | Нет | Порт HTTP-сервера (по умолчанию 8099) | `8099` |
| `DB_HOST` | Да | Хост PostgreSQL | `localhost` |
| `DB_PORT` | Да | Порт PostgreSQL | `5433` |
| `DB_USER` | Да | Пользователь PostgreSQL | `admin` |
| `DB_PASS` | Да | Пароль пользователя БД | `secure_password` |
| `DB_NAME` | Да | Имя базы данных | `qa2a` |
| `ENCRYPTION_KEY` | Да | Мастер-ключ AES-256 для шифрования паролей iiko (≥ 32 символов) | `random_secret_string_32_chars_min` |
| `EXTERNAL_API_KEY` | Да | Ключ для взаимодействия с сервисом QA2A | `qa2a_api_secret` |
| `AI_API_KEY` | Да | API-ключ для LLM (Google Gemini / OpenAI compatible) | `AIzaSy...` |
| `AI_BASE_URL` | Нет | URL эндпоинта генерации текста | `http://127.0.0.1:20128/v1/chat/completions` |
| `AI_MODEL` | Нет | Список моделей через запятую в порядке приоритета | `gemini/gemini-3.5-flash,gemini/gemini-3.0-flash` |
| `QA2A_URL` | Нет | Базовый URL сервиса QA2A | `http://127.0.0.1:8082` |
| `BOT_TOKEN` | Нет | Токен Telegram-бота для отправки алертов о скачках цен | `123456:ABC-DEF...` |
| `APP_BASE_URL` | Нет | Базовый веб-адрес приложения для инвайт-ссылок | `https://moztech.ru/bugh-team/` |
| `ALLOWED_ORIGINS` | Нет | Дополнительные разрешенные CORS-источники через запятую | `https://my-domain.ru` |

## 🛠️ Запуск и тестирование

### Локальный запуск
```bash
# Установка системных утилит (для OCR PDF)
# Ubuntu / Debian: sudo apt-get install -y poppler-utils
# Alpine: apk add poppler-utils

go run .
```

### Запуск тестов
Все ключевые компоненты покрыты модульными тестами (криптография, лимитеры, анти-SSRF, парсинг, сверка):
```bash
go test -v ./...
```

### Сборка Docker-контейнера
```bash
docker build -t iiko-parser:latest .
docker run -d -p 8099:8099 --env-file .env iiko-parser:latest
```

Проверка здоровья сервиса:
```bash
curl http://localhost:8099/health
# {"status":"ok","service":"iiko_parser"}
```

## 🔒 Безопасность и эксплуатация
* В репозитории не хранятся пароли, приватные ключи и файлы `.env` (включены в `.gitignore`).
* Пароли iiko шифруются исключительно на уровне приложения перед записью в базу данных.
* Пароли пользователей учетной системы хэшируются с помощью `bcrypt` со случайной солью.
* Все эндпоинты аналитики и парсинга валидируют принадлежность заведения текущему пользователю (`checkAccountantAccessUser`).
